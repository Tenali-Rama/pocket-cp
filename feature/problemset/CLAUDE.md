# feature/problemset

## Rules
- Data comes only from `ProblemRepository` and, for each contest's division, `ContestRepository.contests(gym = false)` (`core/data`); never cache or fetch here (ADR 0011). The spoiler toggles live in `SettingsRepository` (`hideProblemTags`, `hideProblemRatings`); this module stores nothing itself.
- Data states follow ADR 0011: cached data at once, no indicator for a background refresh, a `RefreshErrorBanner` over data, a full `ErrorState` only without data, `LoadingPlaceholder` only without data. The pull indicator shows only a refresh the user asked for.
- Searching, filtering and sorting are pure (`ProblemQuery`, `searchProblems` in `ProblemQuery.kt`, `ProblemFilter`, `problemsetUiState`), tested in `ProblemQueryTest` and `ProblemFilterTest`, and run on the view model's injected `computeDispatcher` (`Dispatchers.Default`), never on main.
- The query, sort, filters and random pick live in `SavedStateHandle` (`KEY_QUERY`, `KEY_SORT`, `KEY_TAGS`, `KEY_DIVISIONS`, `KEY_RATING` (`[min, max]`), `KEY_PICK`/`KEY_PICK_COUNT`; enums by name), so they survive process death. "Random" draws from the view model's injected `Random`. The text field reads `searchText`, Compose state set on each keystroke, never the async `state`.
- With ratings hidden the rating orders are not offered and the list falls back to Newest (`ProblemsetOptions.effectiveSort`); the chosen order returns when ratings are shown again.
- Rows are `core/ui`'s `ProblemRow` with both toggles applied to every row.
- Layout follows the window width class (`LocalWindowLayout`): compact shows the search field, Filters/Random and sort chips above the list; medium shows search pane | list; expanded shows search pane | list | filter panel. On compact and medium the filters are `FilterSheet`, drawn inside this window (not a dialog), so screenshots and Maestro see it.
- While "Hide tags" is on, the tag chips sit behind "Show tag filter"; the rating and division filters stay open.
- Test tags are Maestro ids, so never rename one: `problemset_search`, `problemset_search_clear`, `problemset_menu`, `problemset_sort_<lower-case ProblemSort>`, `problemset_filters`, `problemset_filters_clear`, `problemset_filters_done`, `problemset_filter_sheet`, `problemset_rating`, `problemset_show_tags`, `problemset_tag_<tag, spaces as _>`, `problemset_division_<lower-case ContestDivision>`, `problemset_random`, plus `core/ui`'s `problem_<display>`. The menu items `problemset_hide_tags` and `problemset_hide_ratings` sit in a popup window, which does not expose tags as resource ids: Maestro taps their text.
- The view model is built by `ProblemsetEntry` with `viewModel { }` (ADR 0012); `ProblemsetScreen` stays stateless for screenshots, which show `problemset.problems.json` (`FixtureProblems`).
